# API接口跳转逻辑说明（对话场景）

## 核心流程概述

基于项目的三个主要模块（记录师、分析师、调理师），正常对话场景的接口跳转逻辑如下：

## 详细流程说明

### 1. 初始化阶段：开始对话

**触发条件**：用户首次访问系统，需要开始情绪评估对话

**接口调用**：
- **路径**: `/recorder/converse`
- **方法**: `POST`
- **参数**:
  ```json
  {
    "user_input": "用户初始输入（如'我最近心情不太好'）"
    // 不提供session_id，系统会自动创建新会话
  }
  ```

**响应处理**：
- 记录师会返回引导性问题，如"能具体说说是什么事情让你感到心情低落吗？"
- 前端保存返回的`session_id`，用于后续对话
- `next_action` 为 `continue_dialogue`，表示需要继续对话

### 2. 对话阶段：持续交互

**触发条件**：用户回复记录师的问题，需要继续对话

**接口调用**：
- **路径**: `/recorder/converse`
- **方法**: `POST`
- **参数**:
  ```json
  {
    "user_input": "用户回复内容",
    "session_id": "之前保存的会话ID"
  }
  ```

**响应处理**：
- 记录师会根据用户回复继续提问或进行总结
- 前端持续保存`session_id`
- 当`next_action`仍为`continue_dialogue`时，重复此步骤
- 当`next_action`变为`trigger_analyst`时，进入分析阶段

### 3. 分析阶段：触发情绪分析

**触发条件**：记录师认为已收集足够信息，`next_action`为`trigger_analyst`

**接口调用**：
- **步骤1**: 获取记录ID
  - 从记录师最后一次响应中提取`record_id`
- **步骤2**: 请求分析
  - **路径**: `/analyst/analyze`
  - **方法**: `POST`
  - **参数**:
    ```json
    {
      "record_id": "从记录师响应中获取的record_id",
      "priority": "high"  // 高优先级，确保快速分析
    }
    ```

**响应处理**：
- 分析完成后，获取返回的`report_id`
- 进入报告获取阶段

### 4. 报告阶段：获取分析报告

**触发条件**：分析请求完成，获得`report_id`

**接口调用**：
- **路径**: `/analyst/report/{report_id}`
- **方法**: `GET`
- **参数**: `report_id`（从分析响应中获取）

**响应处理**：
- 获取报告内容，包括认知行为分析和中医情志分析
- 前端展示分析结果
- 进入疏导方案生成阶段

### 5. 疏导阶段：生成疏导方案

**触发条件**：获取到分析报告，需要生成个性化疏导方案

**接口调用**：
- **路径**: `/therapist/generate-plan`
- **方法**: `POST`
- **参数**:
  ```json
  {
    "report_id": "从分析报告中获取的report_id",
    "user_preference": "balanced"  // 平衡CBT和中医方法
  }
  ```

**响应处理**：
- 获取生成的疏导方案
- 前端展示疏导方案详情
- 可选择性获取策略模板，丰富前端展示

### 6. 增强阶段：获取策略模板

**触发条件**：需要在前端展示更多可选的干预策略

**接口调用**：
- **路径**: `/therapist/strategies`
- **方法**: `GET`

**响应处理**：
- 获取可用的CBT策略、中医策略和综合方法
- 前端展示策略选项，供用户参考

## 异常处理与分支逻辑

### 异步分析处理

当分析任务优先级为`normal`或`low`时：
1. 分析请求会进入后台队列
2. 响应中`status`为`queued`，包含`estimated_completion_time`
3. 前端可选择：
   - 轮询分析状态（通过`request_id`）
   - 提供`callback_url`，等待系统回调通知
4. 分析完成后，获取`report_id`，继续后续流程

### 对话中断处理

如果用户中断对话后重新进入：
1. 前端使用之前保存的`session_id`继续对话
2. 记录师会基于历史对话继续引导
3. 流程从对话阶段继续

### 错误处理

- **接口调用失败**：显示友好错误信息，引导用户重试
- **分析失败**：提示用户分析失败原因，建议重新对话
- **疏导方案生成失败**：提示用户系统暂时无法生成方案，建议稍后重试

## 前端实现建议

1. **会话管理**：
   - 使用浏览器本地存储（localStorage）保存`session_id`
   - 会话过期时间设置合理（如24小时）

2. **状态管理**：
   - 维护当前对话状态（对话中、分析中、方案生成中）
   - 使用加载状态提示用户系统正在处理

3. **用户体验优化**：
   - 分析和方案生成过程中显示进度条或倒计时
   - 提供清晰的导航，允许用户在不同阶段之间跳转

4. **错误边界**：
   - 实现全局错误处理，捕获API调用错误
   - 提供重试机制和用户友好的错误提示

## 总结

此跳转逻辑设计符合正常的情绪评估对话场景，从初始对话到生成疏导方案的完整流程清晰连贯。前端开发者可以根据此逻辑实现用户友好的交互界面，确保用户在整个过程中获得流畅的体验。

关键在于正确处理会话管理、异步任务和错误情况，以确保系统在各种场景下都能稳定运行，为用户提供有效的情绪疏导服务。
